# Промпти для агентів Playwright

Підставте значення замість `<...>`.

## Planner

```
Використай агента playwright-test-planner.

Ціль: <фіча, напр. "пошук статей">
URL: <адреса>
Playwright-проєкт: <назва з playwright.config.ts> (baseURL і testIdAttribute бери звідти)

Умови:
- Працюй лише через playwright-cli у терміналі. MCP не використовуй.
- Seed-тесту нема, і створювати його не треба. Відкрий URL напряму і познач у плані "Seed: none".
- Після open і reload чекай появи ключового елемента (цикл eval до 8 разів з паузою 1 с), а потім роби snapshot.
- План спирайся лише на те, що побачив. Усе, що не перевірив, винеси в розділ "Not verified".
- Для елементів бери data-testid.
- Збережи в specs/<фіча>.plan.md. Сценаріїв 4–6, незалежних, з блоками "expect".
- Закрий браузер і не лишай фонових процесів.

У кінці дай: шлях до плану, список виконаних команд playwright-cli, точні помилки і невиконані кроки.
```

## Generator

```
Використай агента playwright-test-generator.

План: specs/<файл>.plan.md
Сценарії: <номери, напр. 1.1–1.3, або "усі">
Playwright-проєкт: <назва> (тести клади в його testDir)

Умови:
- Працюй через playwright-cli у терміналі. MCP не використовуй.
- Кожен крок плану виконай наживо в CLI. Код тесту роби з того, що CLI надрукував.
- Seed-тесту нема, і створювати його не треба. Починай з page.goto() і чекай ключового елемента.
- Один сценарій дорівнює одному файлу. Ім'я файлу і назву describe бери з плану.
- Перед кожним кроком став коментар "// N. ...".
- Кожен "expect" з плану стає явною перевіркою. Локатори роби семантичні: getByTestId, getByRole.
- Якщо план розходиться з реальним застосунком, виправ план.
- Після кожного сценарію закрий сесію CLI. Потім один раз запусти новий тест: PLAYWRIGHT_HTML_OPEN=never npx playwright test <файл> --project=<проєкт>

У кінці дай: створені файли, результат запуску кожного тесту, зміни в плані, помилки.
```

## Healer

```
Використай агента playwright-test-healer.

Що лагодити: <файл або папка, або "усі тести проєкту <назва>">
Playwright-проєкт: <назва>

Умови:
- Працюй через Bash і playwright-cli. MCP не використовуй.
- Запускай з PLAYWRIGHT_HTML_OPEN=never. Спочатку знайди падіння, потім лагодь по одному.
- Для кожного падіння: npx playwright test <файл:рядок> --debug=cli у фоні, потім playwright-cli attach. Зроби snapshot, перевір console і requests.
- Визнач причину: селектор, таймінг, дані чи реальна зміна в застосунку. Це може бути і баг застосунку.
- Правь лише ті тести, що падають. Нових сценаріїв не додавай.
- Не використовуй networkidle і жорсткі sleep.
- Якщо тест правильний, а застосунок зламаний, познач test.fixme() з коментарем, що відбувається.
- Після кожної правки зупини фоновий запуск і перезапусти тест.

У кінці дай: що падало, причина кожного падіння, що змінено, що пройшло, що позначено fixme.
```
